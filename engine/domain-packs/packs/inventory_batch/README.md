# 库存与批次领域包

`inventory_batch@1.0.0` 提供物料、仓库、库存批次和不可变库存流水，能力 ID 为 `inventory.core`。核心包可独立运行，不内置采购、审批、项目或资产模型。

## 数据与写入边界

| 实体 | 用途 | 写入边界 |
| --- | --- | --- |
| `material` | 物料、单位和效期预警天数 | 领域命令创建、更新 |
| `warehouse` | 仓库主档 | 领域命令创建、更新 |
| `inventory_batch` | 物料、仓库、业务批次号和当前余额 | 仅库存领域命令写入 |
| `inventory_transaction` | 入库、领用、退库和调整流水 | 系统管理，只追加 |

四个实体均禁止通用仓储直接创建或修改。批次以 `material_code + warehouse_code + batch_no` 唯一；所有余额更新使用期望版本执行条件更新。

## 库存事务

`InventoryService` 提供首次入库、后续入库、领用、退库和正负调整。调用方负责开启 SQLite 事务，服务在同一事务中更新批次余额、追加流水并写入审计；流水或审计失败时整体回滚。

余额按以下公式保持一致：

```text
当前余额 = 入库 + 退库 + 盘盈 - 领用 - 盘亏
```

- 数量必须为有限正数，并符合 `quantity_scale`（0 至 6）配置。
- 领用不会自动选择批次，且不能领用已到期、停用或余额不足的批次。
- 退库必须引用当前领用人本人、同批次的原领用流水；所有关联退库累计不能超过原领用量。
- 调整必须提供原因，盘亏后的余额不能小于零。
- 原领用流水永不修改，批次存在任意流水后禁止硬删除。
- 物料或仓库停用后，关联批次不能继续入库、领用、退库或调整。

领用前会依次执行 `InventoryContext.issueBlockers`。桥接包可通过只读查询接口检查申领审批等前置条件并返回稳定阻断码；阻断器无法获得原始 SQLite 写连接。

## 效期

物料定义 `expiry_warning_days`，批次定义可选 `expires_at`。运行时基于注入时钟计算：

- 无到期日：`not_applicable`
- 当前日期等于或晚于到期日：`expired`
- 距离到期日不超过预警天数：`warning`
- 其他：`normal`

## 角色

- `inventory_keeper`：首次/后续入库、库存调整、查看批次和流水。
- `inventory_requester`：领用、退库、查看库存。
- `inventory_reviewer`：查看流水并执行受控调整。
- `inventory_admin`：维护物料和仓库，查看库存数据。

权限只允许尝试命令；领域服务仍校验批次状态、余额、来源流水、日期和乐观版本。

## 种子数据

```ts
generateInventorySeed({ seed, materialCount, warehouseCount, batchCount })
```

`seed` 使用无符号 32 位整数。生成器使用固定基准时间和 xorshift32，相同参数产生字节稳定的数据；批次引用有效物料和仓库，流水净额等于批次余额，并覆盖正常、预警、过期和无效期四类状态。数据不包含真实企业或个人身份。

## 扩展边界

核心包公开物料、批次和流水的字段/关系扩展点，以及批次详情页签和创建来源扩展点。审批、项目任务和资产备件关系应由显式依赖 `inventory.core` 的桥接包追加；桥接包不能绕过 `InventoryService` 直接修改余额或流水。

UI 描述符只包含纯数据，并注册库存流水、领退记录、效期状态、业务操作和库存概览。库存概览按注入时钟动态返回预警批次数、过期批次数和最近 10 条流水，不用静态蓝图过滤冒充动态指标。生产插件固定注册迁移、服务、显式 IPC、UI 与真实 SQLite 验收场景。

## 验证

从 `engine/domain-packs` 执行：

```powershell
npm run typecheck
npm test
npm run build
```

验收场景通过生产插件路径，在真实 SQLite 中执行物料/仓库配置、首次入库、领用、部分退库和盘盈，并核对余额、版本、流水与审计。
