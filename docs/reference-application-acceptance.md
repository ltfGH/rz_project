# 资产巡检整改管理软件验收说明

## 交付范围

参考软件使用与生成项目相同的领域包组合器、锁文件、生产插件目录、Electron 运行时和 NSIS 安装链路。软件可在 Windows 10/11 x64 环境离线运行，不依赖浏览器、Node.js、开发服务器或外部业务系统。

业务界面共 12 个：资产分类、资产台账、责任关系、状态历史、巡检计划、巡检任务、检查项、巡检历史、服务目录、SLA 策略、工单管理、工单历史。另提供“数据与备份”系统界面。

## 业务闭环

主流程为：建立资产 -> 建立巡检计划和任务 -> 执行检查并记录异常 -> 自动且幂等地创建整改工单 -> 分派、受理、处理、提交解决 -> 复核关闭工单 -> 归档巡检 -> 停用资产。

三个桥接包分别负责资产与工单、资产与巡检、巡检与整改工单之间的关系、阻断规则和跨包命令。跨表写入使用调用方持有的同一个 SQLite 事务；核心状态只能由所属领域服务转换。越权操作、重复异常提交和未关闭工单时提前归档均被拒绝。

## 演示角色

| 账号 | 角色 | 职责 |
| --- | --- | --- |
| `dispatcher` | 调度人员 | 计划、任务和工单分派 |
| `operator` | 处理人员 | 巡检执行和整改处理 |
| `reviewer` | 复核人员 | 工单复核和巡检归档 |
| `administrator` | 系统管理员 | 资产维护、备份与恢复 |

交付资源仅保存 scrypt 密码摘要。验收密码通过独立安全渠道交付，禁止写入仓库、安装包、验收报告或日志。

## 数据与锁定

默认种子固定为 1000 条计数业务记录，身份、权限、审计和迁移记录不计入该数字。资源目录包含 `blueprint.json`、`seed.json`、`domain-lock.json`、`project.lock.json`、`production-runtime-catalog.cjs` 和 `resource-manifest.json`；启动和包体验证都会校验锁定关系与 SHA-256。

运行数据库和备份位于 Electron 当前用户的 `userData` 目录，不在安装目录内。卸载不删除用户数据。升级必须保持应用 ID，使用前向迁移，并在打开数据库前验证项目锁和资源清单；不支持用旧版本覆盖新架构数据库。

## 验证命令

领域层执行类型检查、全部单元/集成测试、8 种组合测试、构建和生产目录构建。桌面层执行类型检查、单元/集成测试、参考资源构建、Electron 闭环测试、Windows 安装包构建、解包校验和隔离安装/卸载校验。

机器可读证据由 `tools/write-acceptance-report.cjs` 写入 `dist/reports/reference-acceptance.json`，包含测试数量、资源哈希、种子统计、重启持久化、包体和安装器状态；报告不包含密码或本机绝对路径。

参考 E2E 使用发布资源和打包后的 `win-unpacked` 可执行文件，临时生成四个高熵密码及其 scrypt 摘要。明文只存在于测试进程内，不写入资源、报告或日志。验收覆盖越权拒绝、未归档巡检阻断资产停用、异常自动建单、重复提交拒绝、未关闭整改时阻断归档、完整关闭流程、SQLite 直接检查和重启后的 UI 状态。

桥接失败注入与同事务回滚由领域包和桌面命令 IPC 集成测试执行，不在发布包中保留故障注入入口。公开运行时会先以状态和乐观版本拒绝重复检查结果，E2E 另行确认最终只有一条巡检整改关联和一个整改工单。
